# Machos.uz — сайт продукции

Одностраничный сайт снек-бренда **Machos.uz**: курт четырёх форм, сырные палочки,
сырная косичка и солёные семечки. Формы заявки на сайте нет — все обращения
идут через телефон. Чёрно-жёлтая гамма взята с упаковки, товар
показан настоящими фотографиями с вырезанным фоном, пачка выбранного продукта
висит в 3D-сцене и поворачивается за курсором.

Интерфейс на **двух языках — русском и узбекском**, переключатель в шапке,
выбор запоминается.

## Запуск

Сайт статический, сборка не нужна:

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать `index.html` двойным кликом нельзя — браузер заблокирует ES-модули по
протоколу `file://`. Нужен локальный сервер (команда выше, `npx serve`,
Live Server в VS Code) или обычный хостинг.

## Структура

```
index.html            весь сайт: разметка, стили, тексты, 3D-сцена
assets/               фотографии товара с вырезанным фоном (.webp)
vendor/three/         Three.js r169 — лежит в репозитории, CDN не нужен
dist/machos.html      сборка одним файлом
build-standalone.py   собирает dist
```

Единственный внешний запрос — шрифты Google Fonts (Rubik + Manrope); если они не
загрузятся, подставятся системные.

## Что и где менять

Всё содержимое лежит в первом `<script>` внутри `index.html`:

| Что | Где |
| --- | --- |
| Товары: названия, описания, вес, состав | массив `PRODUCTS` |
| Телефоны, почта, адрес | объект `CONTACTS` |
| **Ссылка на Facebook**, Instagram, Telegram | `CONTACTS.socials` |
| Тексты интерфейса на обоих языках | объект `I18N` |
| Бегущая строка | объект `TAPE` |
| Категории фильтра | массив `CATS` |

### Два языка

Каждый видимый текст помечен атрибутом `data-i18n="ключ"`, перевод берётся из
`I18N.ru` и `I18N.uz`. Чтобы поправить надпись, найдите ключ и измените обе
строки. У товаров переводы лежат прямо в карточке (`ru` и `uz`).

### Ссылки на соцсети

```js
socials: [
  { name:'Facebook',  url:'https://www.facebook.com/share/1HkTk4ZkMF/' },
  { name:'Instagram', url:'https://www.instagram.com/machos_uz' },
],
```

Пока `url` пустой, кнопка показывается приглушённой и не кликается: место под
ссылку видно, но посетитель никуда не уйдёт.

### История компании

Раздел «История» собирается из массива `HISTORY`: четыре вехи, у каждой
заголовок и абзац на двух языках. Год выводится, только если поле `year`
заполнено — сейчас указан лишь `2012`, у остальных вех поле пустое.

```js
{ year:'2012', ru:{ h:'Начал один', p:'…' }, uz:{ h:'…', p:'…' } },
```

Даты от заказчика: 2012 — начало в Ташкенте в одиночку, 2013 — открытие
цеха, начало февраля 2014 — наём работников. Поле `year` принимает либо
строку (`'2013'`), либо пару переводов (`{ru:'…', uz:'…'}`) — так сделана
дата с названием месяца.

### Консультация и бонусы

Кнопка «Консультация» в шапке открывает окно: три шага работы представителя
и лестница бонусов за объём заказа. Всё настраивается в объекте `CONSULT`:

```js
tiers: [
  { sum:200000,  kind:'min', ru:'Минимальная сумма заказа', uz:'…' },
  { sum:500000,  ru:'Скидка 5%',  uz:'5% chegirma' },
  { sum:750000,  ru:'Скидка 10%', uz:'10% chegirma' },
  { sum:1000000, kind:'top', ru:'Фирменная стойка в подарок', uz:'…' },
]
```

`kind:'min'` помечает нижнюю ступень (сумма показывается как «от …»),
`kind:'top'` подсвечивает верхнюю жёлтой рамкой. Суммы в сумах, порядок —
по возрастанию, разряды расставляются сами.

### Фотографии товара

Фото ищется по имени `assets/<id>.webp` (а также `.png`, `.jpg`, `.jpeg`).
**Позиция без фотографии на сайте не показывается.** Сейчас фотографии есть
у всех десяти позиций.

| Файл | Товар |
| --- | --- |
| `assets/seeds.webp` | семечки с солью |
| `assets/kurt-cube.webp` | курт кубиками |
| `assets/kurt-ball.webp` | курт шариками |
| `assets/kurt-stick.webp` | курт палочками |
| `assets/kurt-big.webp` | курт крупными кусками |
| `assets/kurt-ball-12.webp` | курт шариками, большая пачка |
| `assets/sticks-cyan.webp` | сырные палочки, бирюзовая упаковка |
| `assets/braid-green.webp` | сырная косичка, зелёная упаковка |
| `assets/sticks.webp` | сырные палочки |
| `assets/braid.webp` | сырная косичка |

Фон у снимков вырезан: контур строится по печати на упаковке, поэтому пачка
висит в сцене силуэтом, а не прямоугольной плиткой. Новые фотографии нужно
обрабатывать так же — снимок с фоном на тёмном сайте выглядит заплаткой.

### Кнопки звонка и почты

Телефон и адрес почты — обычные ссылки `tel:` и `mailto:`, они берут значения
из `CONTACTS`. На телефоне такая ссылка открывает набор номера или почтовое
приложение.

К письму заранее подставляется тема (ключ `mail.subject` в `I18N`), поэтому в
ящике сразу видно, что письмо пришло с сайта. Тема переводится вместе с
интерфейсом.

Обе ссылки обрабатываются одним обработчиком:

- набор или почта открываются отдельным окном — так работает и внутри
  встроенного просмотрщика, где обычный переход блокируется;
- на компьютере, где звонить и писать часто нечем, номер или адрес
  копируется в буфер и всплывает подсказка.

### Экран загрузки

При заходе показывается чёрный экран с логотипом Machos.uz и полосой
прогресса. Полоса ползёт к цели, которую двигают вехи: разметка загружена
(25%), фотографии найдены (70%), сцена отрисовала первый кадр (100%).

Когда полоса доходит до конца, экран плавно гаснет и удаляется из
разметки. Сторожевой таймер на 7 секунд снимает его в любом случае —
страница не залипнет, даже если что-то не загрузится.

## Доступность и запасной вариант

- Если WebGL недоступен, вместо сцены показывается обычная фотография.
- При системной настройке «уменьшить движение» анимации отключаются.
- Навигация с клавиатуры, `aria`-атрибуты у меню, фильтра и переключателя
  языка, ссылка «Перейти к содержимому» в начале страницы.
- На узких экранах сцена приглушается, чтобы текст оставался читаемым.

## Один файл для отправки

`dist/machos.html` — вся страница вместе со встроенным Three.js и
фотографиями. Открывается двойным кликом, работает без интернета, кладётся на
любой хостинг как есть. Пересобирается после правок:

```bash
python3 build-standalone.py
```

## Кабинет для своих

Закрытый раздел по адресу **`/cabinet/`** — отдельная страница, с витрины на неё
ссылок нет и в поиск она не попадает. Заходят только те, чей номер записан в
базе; регистрации нет by design: при четырёх людях список ведётся вручную.

**Вход по имени и паролю.** Сверху имя, снизу шесть цифр. Пароли
придумывают сами люди, одноразовых кодов и SMS нет — при двух-четырёх
сотрудниках это лишний слой.

Пароль в базе не хранится: лежит только bcrypt-отпечаток, из которого его не
достать. Сравнение идёт внутри Postgres, наружу отпечаток не выходит вообще.
Пять неверных попыток подряд — и вход под этим именем закрывается на
15 минут; при таком счёте перебрать миллион вариантов невозможно.

Имя запоминается в браузере, так что при следующем заходе остаётся ввести
только пароль. Сеанс живёт 12 часов.

### Сервер

Supabase, проект `machos-cabinet` (регион Франкфурт — ближайший к Ташкенту).
Бесплатный тариф. Таблицы закрыты полностью: RLS включён, политик нет,
поэтому снаружи не читается ничего — работает только серверная функция
`auth` со служебным ключом.

| Таблица | Что хранит |
| --- | --- |
| `staff` | кто допущен: имя, роль, отпечаток пароля |
| `sessions` | выданные входы, живут 12 часов |
| `site_content` | содержимое витрины: черновик и опубликованное |
| `leads` | журнал звонков и заявок |
| `documents` | описания файлов; сами файлы — в хранилище `docs` |
| `settings` | ключ бота и соль для отпечатков |

**Добавить человека:** вкладка «Люди» в самом кабинете — она видна владельцу.
Имя, права и шестизначный пароль. Там же вход закрывается, не удаляя человека,
и снимается блокировка после неудачных попыток. Каждый может сменить себе
пароль на той же вкладке; у сотрудника она называется «Пароль» и содержит
только это.

### Что в кабинете

**Заявки.** Журнал обращений: кто позвонил, когда, из какого магазина, что
заказал и на какую сумму. Заполняется вручную — на витрине формы нет, все
обращения идут через телефон. Есть поиск по имени, телефону, точке и товару
и три состояния: новая, выполнена, отказ.

**Документы и цены.** Прайсы, договоры, макеты упаковки, сертификаты —
разложены по видам, у каждого файла название и заметка. Сами файлы лежат в
закрытом хранилище `docs`: ссылка на скачивание выдаётся только вошедшему и
живёт десять минут, так что переслать её наружу бесполезно. До 25 МБ на файл;
имя в хранилище задаёт сервер, от исходного остаётся только расширение.

**Товары, Контакты, История, Бонусы.** То же содержимое, что видно на
витрине, только в виде полей. Правки копятся в черновике; кнопка
**Сохранить** прячет их на сервере, кнопка **Опубликовать** выкладывает
на сайт. Метка в шапке всегда говорит, в каком вы состоянии: «черновик ещё
не сохранён», «сохранено, на сайте ещё нет» или «всё опубликовано».

Перед публикацией содержимое проверяется: пустой список товаров, товар без
названия, повторяющееся имя файла или пустой телефон на витрину не уйдут.

### Как витрина берёт содержимое

При загрузке страница спрашивает у сервера опубликованное содержимое и ждёт
его **не дольше полутора секунд**. Молчит сервер — показывается то, что вшито
в саму страницу, и посетитель ничего не замечает. Поэтому витрина работает
всегда: свежесть зависит от сервера, работоспособность — нет.

Файл `content.json` в корне — снимок вшитого содержимого. Панель берёт его
как отправную точку, когда черновика ещё нет.

После публикации правки видны в течение минуты: ответ сервера кэшируется
на 60 секунд.

## Публикация

Сайт опубликован на **GitHub Pages**:

**https://jafarjakhongirovich-lgtm.github.io/Public/**

Боевая ветка — `main`. Каждый пуш в неё запускает рабочий процесс
`.github/workflows/pages.yml`, который выкладывает содержимое репозитория как
есть: сборки нет, сайт статический. Выложить вручную можно там же —
вкладка Actions, «Публикация сайта», кнопка **Run workflow**.

Чтобы это заработало, в настройках репозитория один раз включены:
Settings → Pages → Source = **GitHub Actions**, и Settings → Actions →
Workflow permissions = **Read and write**. Репозиторий публичный — на
бесплатном тарифе Pages иначе не работают.

### Свой домен

Settings → Pages → **Custom domain** → `machos.uz` → Save. GitHub положит в
репозиторий файл `CNAME` и сам выпустит сертификат. У регистратора домена
нужно прописать записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `jafarjakhongirovich-lgtm.github.io` |

Сертификат выпускается сам, когда записи разойдутся по DNS: от нескольких
минут до пары часов. После подключения домена сайт открывается по адресу
`machos.uz`, без `/Public/` в конце — ссылки внутри страницы относительные и
работают в обоих случаях.

поднимется без сборки.
